# Nautilus Rules

Nautilus Rules combines domain and IP data to generate geographic databases and rule sets for proxy kernels. The build organizes direct, proxy, advertising, and service categories, producing full and slim datasets together with Mihomo MRS and sing-box rule files.

## Get the data

Databases and bundles are generated by [.github/workflows/release.yml](.github/workflows/release.yml). After a successful publication, the `latest` dataset is available from [Releases](https://github.com/velnora-client/nautilus-rules/releases); confirm that the required version and files exist before use.

| Format | Build outputs |
| --- | --- |
| Country IP data | `country.mmdb`, `country-lite.mmdb` |
| V2Ray geographic data | `geoip.dat`, `geoip-lite.dat`, `geosite.dat`, `geosite-lite.dat` |
| sing-box databases | `geoip.db`, `geoip-lite.db`, `geosite.db`, `geosite-lite.db` |
| Meta IP databases | `geoip.metadb`, `geoip-lite.metadb` |
| ASN data | `GeoLite2-ASN.mmdb` |
| MRS bundle | `BundleMRS.7z` |

The build generates `.sha256sum` files for published assets. Download the matching checksum file and verify it from the same directory, for example:

```sh
sha256sum -c geosite.dat.sha256sum
```

Generated branches have the following layout:

- `release`: databases, bundles, and checksum files.
- `meta`: Mihomo MRS rules, including `geo/geosite`, `geo/geoip`, slim rules, and ASN data.
- `sing`: sing-box rule sets organized into corresponding categories.

These are workflow output targets. If a required release or branch does not yet exist, complete the data build first. `latest` is a rolling version whose contents change with upstream data.

## Use with Mihomo

Place the generated China domain rule file `geo/geosite/cn.mrs` at the local path `./provider/rule-set/geosite-cn.mrs`. The following configuration routes matching traffic directly:

```yaml
rule-providers:
  cn:
    type: file
    behavior: domain
    format: mrs
    path: ./provider/rule-set/geosite-cn.mrs
rules:
  - RULE-SET,cn,DIRECT
  - MATCH,DIRECT
```

Confirm that the file exists and the kernel supports MRS. For automatic HTTP updates, change the provider to `type: http` and configure an accessible data URL and `interval`. Raw file URLs in private repositories require authentication and cannot be assumed to support anonymous distribution. Full and slim `geosite` datasets differ in categories and coverage; they are not lossless substitutes. Rules control matching and routing, and do not guarantee service access or replace real network verification.

## Data and build pipeline

[resouces](resouces) holds the project's additions and removal lists; this spelling matches the source directory. The workflow fetches community domain sources, merges and deduplicates them, invokes upstream builders to generate geosite data, converts geoip/geosite data, produces rule files and checksums, and publishes the Release and data branches.

The main workflow is scheduled daily at `22:30 UTC` and also supports manual dispatch. Actual execution depends on repository Actions settings, permissions, and external services. The full pipeline accesses multiple external data sources and uses Go, Python, Bash, GNU text utilities, `geo`, 7-Zip, and GitHub CLI, with publication permissions required.

This repository is not a Go or Node application and has no unified `make build` or test entry point. To rebuild, prepare the upstream checkouts and intermediate files specified by the workflow; running `go build` directly at the repository root is insufficient.

## Local helper scripts

[scripts/convert-clash.sh](scripts/convert-clash.sh) generates Clash lists and YAML from `geoip.dat` and `geosite.dat` in the current directory. It requires an executable `./mosdns` in that directory:

```sh
bash scripts/convert-clash.sh
```

[scripts/convert.sh](scripts/convert.sh) also uses a local `./sing-box` to compile sing-box rules. These scripts assume all inputs and tools are already available, use GNU `sed`, and write or replace contents under `geoip/` and `geosite/` in the current directory. Run them in a dedicated working directory. The converters specified in the workflow define the main publication pipeline.
